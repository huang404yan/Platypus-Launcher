# S1 真机实验清单（用户可执行）

本文回答 S1：「手机到底能不能跑 Minecraft Java 版，跑成什么样」。
**不需要等我们写出 runtime-android。** 用现成成品（PojavLauncher）当探针，一台手机、两小时就能定标；我们的启动器再按这个结论决定做到哪一步。

所有实验都由你在手机上做，把结果填进 §7 的表格发回来。**下面的「预期」全部是推断，不是实测** —— 你填的数字才是实测。

---

## 0. 为什么要用别的启动器做实验

我们的 Android 端目前只有「选版本 / 下载 / 建实例 / 自检」，启动链路（应用内 JVM + LWJGL 替身 + 渲染翻译层）还没写。这条路能不能走通、走通了跑多快，完全取决于**平台本身的硬条件**：

- 手机的 Vulkan/GLES 驱动质量；
- 内存够不够 JVM 堆；
- 系统会不会因为内存压力把游戏进程杀掉。

这三件事与我们写不写代码无关。**PojavLauncher 已经把同样的技术路线跑通了**，所以它是目前最便宜的定标工具 —— 花 20 分钟装它、跑一次，就能替我们省掉两周的盲目开发。

> 这一步不是「抄它」，是「用它的成品测我们关心的平台上限」。测完我们仍然自己写实现。

## 1. 准备

| 项 | 要求 |
|---|---|
| 手机 | 就是你要日常用的那台（**不要借别人的**，我们要的是你这台的真实数据） |
| 存储空闲 | **≥ 2 GB**（1.20.1 本体 706 MiB + JRE 161 MiB + 余量） |
| 网络 | Wi-Fi 优先。**记下你的实际带宽**（用测速 App 或看下载页面显示的速度） |
| 对照启动器 | PojavLauncher（见 §2 装法） |
| 笔和纸 / 备忘录 | 记录用，每步都要记 |

**先记下三条基线**（后面所有实验都要对照）：

1. 手机型号 + Android 版本 + 内存大小（设置 → 关于手机）。
2. 存储空闲空间（设置 → 存储）。
3. 你的 Wi-Fi 实测下载速度（MB/s）。

## 2. 装对照启动器（PojavLauncher）

1. 打开 GitHub Releases 页：`https://github.com/PojavLauncherTeam/PojavLauncher/releases`
   - 如果打不开，用镜像：在前面加 `https://gh-proxy.com/`，即 `https://gh-proxy.com/https://github.com/PojavLauncherTeam/PojavLauncher/releases`
2. 下最新一个 `app-debug.apk` 或 `PojavLauncher-*.apk`（约 30–40 MB）。
3. 装（和装我们的一样，会遇到「未知来源」提示）。
4. 打开，**先不要进游戏**，走 §3 的 E1。

> 安全提示：PojavLauncher 是开源项目，但它要求「所有文件访问权限」和联网。**如果你不愿意在主力机上装第三方启动器，直接跳过 E2–E5，只做 E1 和 E6**，然后告诉我「不便装第三方」，我改用另一个方案（需要你多做几次我们自己的 APK 测试，周期会长一些）。

## 3. 实验

### E1 · 我们的 APK：环境基线采集

**目的**：拿到这台机器的硬条件。所有后续实验的解释都依赖它。

**怎么做**
1. 装我们的 APK：`releases/preview/android/Platypus-Launcher-0.8.0-preview.1-android.apk`
2. 给「所有文件访问权限」（见 10 号文档 §2.1）。
3. 点左侧「诊断」→ 等进度条走完 → 点「复制诊断信息」。
4. 粘贴存档。

**看什么 / 记什么**
- 首选 ABI（`arm64-v8a` 才算主流；如果是 `armeabi-v7a` 就是 32 位机，**没有 Vulkan/Zink 这条路**）
- 总内存 / 可用内存 / 堆上限
- GL_RENDERER 的具体名字（这决定了驱动是谁家的）
- 网络两项的 HTTP 码与耗时

**预期 [推断]**：arm64 + GL_RENDERER 形如 `Adreno (TM) 6xx` 或 `Mali-G7x`，网络探测 200 / 403，耗时 200–1500 ms。

---

### E2 · 我们的 APK：下载实测

**目的**：验证下载器在真机上的吞吐与稳定性，换算「首次安装要多久」。

**怎么做**
1. 我们的 APK → 「下载」→ 选 **1.20.1** → 点「下载到上面这个目录」。
2. **掐表**：从点下去到显示「完成」。
3. 记下最终显示的「N 个文件 / X MB」。
4. 中途**故意锁屏 30 秒再解锁**（测后台存活）。
5. 下载完成后再点一次「下载」→ 应该几乎瞬间完成（已下的文件跳过）。

**看什么 / 记什么**
- 总耗时、显示的总字节数
- 锁屏期间有没有中断（进度条是否归零 / 是否报错）
- 第二次点击是否秒完成

**预期 [推断]**：10 MB/s 下约 70–90 秒；2 MB/s 下 6 分钟。锁屏可能被系统暂停（这不算 bug，但要知道）。

**如果失败**：点「复制失败信息」发回来。这条是所有下载类问题的第一手证据。

---

### E3 · 对照启动器：能不能进世界 + 帧率

**目的**：这是 S1 的核心问题 —— 能不能跑，跑多少帧。

**怎么做**
1. PojavLauncher → 首次启动会走一遍向导（选语言、给权限、JRE 会**自动下载**，约 160 MB）。
2. 版本列表里选 **1.20.1**（**不要选 1.21.x** —— Pojav 只发到 Java 17，1.21 起不来，这正好验证了我们在 09 号报告里写的那条硬约束）。
3. 渲染器设置里保持默认（**GL4ES**，Pojav 里可能叫 `OpenGL ES 2.0/3.0 (gl4es)`）。
4. 内存设置：先用**默认值**，别调。
5. 点启动 → **掐表到出现主菜单**（这是「第二次启动耗时」，不含下载）。
6. 进单人世界（创造模式、默认地形）→ 等区块加载完（约 30 秒）。
7. **看 fps**：
   - 打开游戏内 `F3`（Pojav 里是一个虚拟按键，通常在屏幕上方或侧边）。
   - 看 `fps` 那一行，**记下三个数**：静止时、快速转头时、走动时。
8. 依次改渲染距离 **8 → 6 → 4**，每次记 fps。
9. 退出游戏（**别用系统返回键**，用游戏内菜单的「退出」）。

**看什么 / 记什么**

| 指标 | 记录 |
|---|---|
| 到主菜单耗时 | ___ 秒 |
| 静止 fps（渲染距离 8） | ___ |
| 转头 fps（渲染距离 8） | ___ |
| 静止 fps（渲染距离 6 / 4） | ___ / ___ |
| 画面是否正常（有没有全黑/花屏/贴图错乱） | 正常 / 异常，描述 |
| 手机发热（手感） | 温热 / 烫手 / 很烫 |
| 电量掉了多少（跑 15 分钟） | ___% |

**预期 [推断]**：渲染距离 8 下 15–35 fps；降渲染距离提升明显；画面基本正常但水面/天空可能有瑕疵。

**这是最重要的一个实验。** 如果 E3 的结果是「进得去但 10 fps」或「画面全黑」，那 S1 的结论就是「这台机器不适合」，我们就不该继续投入。

---

### E4 · 对照启动器：Vulkan/Zink 能不能开

**目的**：判断有没有第二条渲染路（能上 GL 4.x、能开光影）。

**怎么做**
1. PojavLauncher → 设置 → 渲染器 → 选 **`Zink (OpenGL 4.x)`** 或名字里带 `zink` / `vulkan` 的那项。
2. 重启启动器（**必须重启**，渲染器是启动时加载的）。
3. 同样进 1.20.1，看能否到主菜单、画面是否正常、fps 多少。
4. 如果黑屏/闪退，**切回 GL4ES**，记下现象。

**看什么 / 记什么**
- Zink 下能否到主菜单
- 画面是否正常
- fps 相比 GL4ES 是升还是降

**预期 [推断]**：中高端机（Adreno 6xx/7xx）可能可用但 fps 未必更高（多一层转换）；低端机直接黑屏。

**这一项的价值**：如果 Zink 可用，我们未来可以给用户「流畅」和「能开光影」两个档；如果不可用，就只有 GL4ES 一条路，产品定位要相应收缩。

---

### E5 · 对照启动器：后台会不会被杀

**目的**：判断「切出去回微信再回来」会不会丢档。

**怎么做**
1. 在 E3 的世界里（已加载完），按 Home 键退到桌面。
2. 打开微信，刷 2 分钟。
3. 切回 PojavLauncher。
4. 观察：是回到了游戏，还是重头加载，还是被杀了？

**看什么 / 记什么**
- 回到游戏 / 重载世界 / 进程被杀（启动器回到主界面）
- 如果被杀了，当时游戏已经玩了多久

**预期 [推断]**：8 GB 内存的机可能存活，6 GB 以下大概率被杀。这直接决定我们要不要做「游戏内定时存档提示」。

---

### E6 · 我们的 APK：存储与路径

**目的**：确认游戏目录的规范位置，避免将来「下载到一个用户找不到的地方」。

**怎么做**
1. 我们的 APK → 「诊断」→ 看「游戏目录」那一节，记下每行的路径与状态。
2. 用手机自带的文件管理器，**手动**去这个路径看一眼：
   - 安卓 11+ 的机型，`/storage/emulated/0/` 就是「内部存储」根目录。
   - 确认文件管理器里能看到 `.minecraft` 文件夹（**以点开头，可能是隐藏的**，文件管理器一般有「显示隐藏文件」开关）。
3. 如果 E3 做过，去 Pojav 使用的目录看一眼（通常在 `/storage/emulated/0/games/PojavLauncher/.minecraft`），记下它的实际路径。

**看什么 / 记什么**
- 我们默认选的路径是什么
- 文件管理器里能不能看到
- Pojav 用的是哪个路径

**为什么重要**：两个启动器用同一个 `.minecraft` 是最省事的（存档、mod、资源包通用）。如果 Pojav 用的是 `games/PojavLauncher/.minecraft`，我们就应该默认指向那里，用户不用搬文件。

## 4. 实验顺序与时间

| 顺序 | 实验 | 预估耗时 | 能不能跳过 |
|---|---|---|---|
| 1 | E1 环境基线 | 3 分钟 | **不能** |
| 2 | E2 下载实测 | 2–10 分钟 | 不能（有网就行） |
| 3 | E6 存储路径 | 3 分钟 | 不能 |
| 4 | E3 能否进世界 + fps | 30–60 分钟（含 JRE 下载） | **不能**（S1 的核心） |
| 5 | E4 Zink | 10 分钟 | 能（不想折腾可跳） |
| 6 | E5 后台存活 | 5 分钟 | 能（但建议做） |

**合计约 1–2 小时**，其中大半是等下载。

## 5. 安全与回滚

- **不要 root**，这些实验都不需要。
- PojavLauncher 会往存储里写 `.minecraft`（约 1 GB）。**不想留就删掉那个文件夹**，它不改系统任何东西。
- 我们自己的 APK 只写 `.minecraft` 和 `.platypus-diag`（诊断页用完自己删）。
- 如果手机明显发烫，停一会儿再做，别硬跑。

## 6. 不想做 E3–E5 的话

直说就行。最小可行集合是 **E1 + E2 + E6**（约 15 分钟），能回答「下载链路在真机上通不通」。但**「能不能跑游戏」这个 S1 的核心问题就答不了**，我会把报告里的相关结论继续标成「推断·未验证」。

## 8. 这些数据会被用来做什么

| 实验结果 | 影响的决定 |
|---|---|
| 首选 ABI 是 32 位 | 放弃 Vulkan 路线，只做 GL4ES；JRE 包体积减半 |
| 堆上限 < 1 GB | 产品定位改为「轻量客户端，只跑原版不跑整合包」 |
| E3 fps < 15 | **S1 判定为「不可玩」**，转向「远程串流」或「只做管理端」 |
| E3 画面全黑 | 换渲染方案（可能要自编 GL4ES 或试 LTW） |
| Zink 可用 | 增加「光影」卖点，但要处理驱动兼容性 |
| E5 被杀 | 必须做定时存档提醒 + 存档备份 |
| E6 路径冲突 | 改默认目录指向 Pojav 的位置，实现存档互通 |

**没有这些数字，09 号报告里所有关于性能的话都只能是区间估计。**
