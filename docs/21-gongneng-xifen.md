## 0 一句话

鸭嘴兽现在的问题是**每条能力都只有一条最细的路径**：能装原版、能装三个加载器、能搜模组装进去、能扫局域网——但每一步都只有「唯一走法」，没有选择、没有分类、没有补救。
所以路线不是「再加十个功能」，而是三段：**补全 → 细分 → 美化**。

---

## 1 判据

D12 那条硬标准继续用：**去掉这一步，用户还能不能双击把游戏玩起来**。
这一轮再加一条**好用判据**（回答用户「功能出来了但不好用」）：

> 一个功能算「好用」，要同时满足三条：① 用户不必先知道实现细节就能用（不用记住「改名去掉 .disabled」）；② 出错时界面说得出下一步（不是只报错）；③ 同一条路至少有第二种走法（列表可点、可手填、可重试）。

## 4 三阶段

### 阶段一：补全（P1–P7）

按 D12 的优先级排：能进游戏 > 能装整合包 > 能联机 > 能迁移 > 安全与体验。

| 序 | 事项 | 为什么排这个位置 | 工作量 |
|---|---|---|---|
| **P1** | **实例真隔离 + 实例详情页**：每个实例有独立 `mods/ saves/ config/ resourcepacks/`，实例卡片能改 Java、能打开目录、能看版本 json 摘要 —— **已完成（2026-11-10）**，见 `docs/22-shili-geli-yu-xiangqing.md` | 不修这条，后面加的 mod 管理、存档管理全是错的（会写进全局目录）。**这是所有后续功能的地基** | 大 |
| **P2** | **模组管理补全**：勾选框启用/停用（改 `.disabled`，一次点击）、删除、检查更新（Modrinth `version_files` 接口）、缺依赖给清单并可一键装 | 用户已经踩到了 E1。改动集中在 `ModsPage` + `ModScanner` 加写操作，不需要新协议 | 中 |
| **P3** | **整合包导入**：`.mrpack`（Modrinth）与 MCBBS v2 zip（PCL/HMCL 通用） | 这是「能装别人给的包」，D12 排第二。做完鸭嘴兽才算能接社区的包 | 大 |
| **P4** | **下载页扩类**：资源包 / 光影包 / 数据包 / 存档；整合包搜索 | 有了 P3 的解析器，这四类只是换 Modrinth 的 `project_type` | 中 |
| **P5** | **整合包导出**（MCBBS v2） | 与 P3 共用格式代码，一起做省一半 | 中 |
| **P6** | **崩溃分析与日志**：退出码 + 关键字归因（`Java 版本不符` / `内存不足` / `模组冲突` / `缺依赖`）、导出日志文件、一键复制 | E8。PCL 的强项就在这，用户感知极强 | 中 |
| **P7** | **服务端**：装 server.jar、改 server.properties、启停、控制台、白名单 | PCL 2026-11-08 才收口的那套。鸭嘴兽要真做的话是独立一大块 | 大 |

**明确排在本轮之外**（理由不是「难」，是「用户现在没有这个需求」或「有硬约束」）：

| 事项 | 理由 |
|---|---|
| 微软正版登录 | 用户 m00737 已定调：延后到整体接近 PCL 自编版再上。离线能玩，不卡闭环 |
| 陶瓦联机 | **有许可证硬约束**：Terracotta 是 AGPL-3.0，鸭嘴兽是 Apache-2.0 且**公开发布二进制**。把陶瓦二进制打进包里会触发 AGPL 的传染条款（整个分发物得按 AGPL）。PCL 自编版敢用是因为它「纯自用不分发」。要做只有两条路：① 首发时让用户自己下陶瓦（启动器只做调用）；② 换一个非 AGPL 的方案。这条**必须先决策再动手** |
| 主题配色 / 背景图片 / 背景音乐 | 属于阶段三美化，先做会把「功能没补全」的问题盖住 |
| 自动更新 | 需要签名与更新服务器，与功能无关 |

功能齐了之后再拆页面，因为**拆页的依据是功能边界**——功能没齐时拆出来的 tab 是空的。

| 序 | 事项 | 形态 |
|---|---|---|
| **S1** | 一级导航改两级 | 左侧 220.dp 主栏 + 二级 tab（PCL 的 `PageInstanceLeft` / `PageSetupLeft` 那种），不再一屏到底 |
| **S2** | 实例页拆四个 tab | 概览 / 设置（内存·Java·JVM 参数）/ Mod / 存档 |
| **S3** | 设置页拆三个 tab | 启动 / 界面（先留位给美化）/ 其他（打开目录、日志、关于） |
| **S4** | 下载页改「左分类 + 右内容」 | 原版 / 整合包 / Mod / 资源包 / 光影 / 数据包 |

| **S6** | 模组页拆「已装 / 浏览」 | 两个 tab，已装那张表加启用开关与删除 |

### 阶段三：美化（U1–U4）

围绕「鸭嘴兽」这个形象，不套通用模板：

| 序 | 事项 | 具体 |
|---|---|---|
| **U1** | 设计令牌 | 主色取鸭嘴的橙黄（`#F2A93B` 一档）+ 湖蓝（`#2E7DAF` 一档），配中性灰；圆角 8/12/16 三档；间距 4 的倍数；字号五档。全部收进一个 `Theme.kt`，不散落在各页 |

## 5 为什么是这个顺序

1. **P1 必须第一个做**：现在所有实例共用一份 `mods/`，如果先做模组管理和整合包，做完发现「装的包全进了同一个目录」，等于白做。
2. **P2 排在 P3 前**：模组管理是小改动、高频使用；整合包是大改动、一次性。先用小改动把「好用」的感觉做出来。
3. **P3 与 P5 一起做**：导入导出共用同一套格式代码（MCBBS v2 的 `mcbbs.packmeta` + `manifest.json`，`.mrpack` 的 `modrinth.index.json`）。分开做要写两遍。
4. **P6 排中段**：崩溃分析不新增任何协议，纯在已有日志上加规则，性价比最高，但排太前会拖慢主线。
5. **P7 服务端最后**：它是一整块独立产品，做完才有「一站式」；但用户现在的痛点是「玩不起来」而不是「开不了服」。
6. **细分一定要等补全之后**：拆页的依据是功能边界。现在拆实例页，四个 tab 里两个是空的。

## 7 与 D12 的关系

D12 定的「本轮链条」是：选版本 → 下载 → 补 Java → 登记实例 → 一键启动进主菜单。**这条链现在全通了**（245 例单测 + 九个冒烟任务 + 真机进主菜单）。
所以本文档不是推翻 D12，而是 D12 里「以后（本轮明确不做）」那一半的**重新排期**：

- D12 说「以后不做」的：正版/离线/Authlib 登录、陶瓦联机、服务器、控制台、RCON、server.properties、OP 管理、Forge/NeoForge 内存改写、主题配色、自动更新、帮助文档。
- 本文档把它们拆成：**P2 模组管理、P3 整合包、P6 崩溃分析、P7 服务端**（进本轮）；**登录、陶瓦、主题、自动更新**（延后，且陶瓦有许可证前提）。
- 新增 D12 没提的：**P1 实例真隔离**——这是做 P2/P3 时才暴露出来的地基问题。

已在 `docs/04-juece-jilu.md` 追加 **D16**（实例真隔离）与 **D17**（实例详情做成「钻进一个」而不是第九个一级入口）记录落地时的取舍；排期本身由本文档承接。
