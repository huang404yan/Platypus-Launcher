# 42 · 两套配色

2026-11-14。启动器原来一直用 Material 3 默认的紫调浅色，那是「没设计过」的样子，
不是选过的样子。这一版给了两套定好的色，并且让孵化版与正式版默认看起来就不一样。

## 一、为什么是「两套」而不是一个调色盘

配色差一档就够用了。做成可选调色盘的结果通常是：用户花十分钟纠结，随便挑一个，
然后每个页面的验收都要乘以主题数量。两套足够区分正式版与孵化版的气质，
也足够让夜里玩的人自己挑一个不刺眼的。

两套都不是随手调的色，按「60% 背景 + 30% 模块 + 10% 强调」配的：

| | 自然原色（Natural，深色） | 特工蓝橙（Perry，浅色） |
| --- | --- | --- |
| 60% 背景 | 深潭青 `#1A2B2C` | 灰白 `#F4F7F6` |
| 30% 模块 | 泥土棕 `#3E2723` | 泰瑞蓝绿兑淡 `#DDEFEC` |
| 10% 强调 | 鸭嘴橙 `#FF8C00` | 亮橙 `#FF7F00` |
| 正文 | 奶油白 `#FDF5E6` | 深灰 `#2C3E50` |
| 默认给谁 | 正式版 | 孵化版 |

几处不是照抄色卡的地方，都是实测出来的：

- **正文不用纯白**。`#FFFFFF` 压在深潭青上盯久了发刺，换成奶油白把对比度压到
  刚好够读的程度。
- **强调色上的字用深色**。白字压 `#FF8C00` 的对比度只有 2.2:1，达不到 4.5:1
  的可读线；换成深棕 `#2A1600` 有 8:1。所以 `onPrimary` 不是白的。
- **浅色那套的模块色兑淡了**。「30% 模块色」指占三成面积那一层；整条侧栏刷饱和的
  `#00A896` 会盖过橙色，10% 的强调就不再是强调。饱和蓝绿留在 `secondary`，
  用在需要「就是个按钮」的地方；侧栏与卡片用兑淡的 `#DDEFEC`。

## 二、默认值按版本给，选过就记住

`LauncherTheme` 有三个值：`AUTO`（跟随版本）、`NATURAL`、`PERRY`。

`AUTO` 不是第三套颜色，是「还没选过」：孵化版解析成 Perry，正式版解析成 Natural。
判断依据是 `Brand.isPreview`（版本号里带 `-preview`）。用户一旦在设置里手点过某一套，
这个值就以字符串形式存进 `settings.json` 的 `theme` 字段，下次启动先读它，
不再看版本号 —— 在孵化版里选了「自然原色」的人，不该因为版本号是 preview 又被掰回去。

存 id 字符串而不是枚举下标：以后加一套色、或者调整枚举顺序，老文件不会读歪。
认不出来的值（手改的、来自以后版本已删掉的主题名）一律当 `AUTO`。

## 三、颜色不许写死在页面里

界面里所有颜色都走 `MaterialTheme.colorScheme.xxx`，全仓库 250 多处引用。
所以换主题只需要换一个 `ColorScheme`，没有一行页面代码需要知道主题存在。
这一条是**先有事实、后有主题**的顺手：写页面的时候就没写死过颜色。

色值本身在 `core/src/main/kotlin/io/github/huang404yan/platypus/core/theme/LauncherTheme.kt`
里，以 ARGB 打包成 `Long`。这样 core 不依赖 Compose 也不依赖 Android 的图形库
（core 是纯 JVM，安卓与桌面共用它）。桌面端 `ui/.../Theme.kt` 与安卓端
`androidApp/.../Theme.kt` 各留一份「Long 转 ColorScheme」的映射，形状一样、都不长。

为什么不把 ColorScheme 直接放进 core：那等于让 core 拖上 Compose，而安卓与桌面的
Compose 版本各自独立升级。

### 最外层要自己铺一层底色（第一版的真实故障）

第一版把 `MaterialTheme(colorScheme = …)` 直接包住页面，结果深色那套一打开就是
「大片刺眼的白 + 看不清的字」：

- 桌面端根容器是 `Row(Modifier.fillMaxSize())`，**没有底色**，露出来的是 Swing 窗口的
  默认白（实测像素 `#F0F0F0`）。浅色主题下白底与 `#F4F7F6` 的 background 几乎一样，
  所以看不出来；深色主题下凡是不被 `Card` 覆盖的空白就全是白。
- 同时 `LocalContentColor` 没有 `Surface` 提供，退回 `Color.Black`。于是同一屏上
  出现了「显式写 `color = onSurface`（奶油白）的标题」和「跟随 `LocalContentColor`（黑）
  的其它文字」—— 前者压在白底上，对比度 1.0:1，等于看不见；后者黑字压白底，看着
  还算正常，这就是为什么只有部分文字「发灰发暗」。

修法不是去调色值（颜色本身算出来全是达标的：正文 11.75:1、次要文字 6.42:1），
而是让 `PlatypusTheme` 在 `MaterialTheme` 里面包一层
`Surface(Modifier.fillMaxSize(), color = MaterialTheme.colorScheme.background)`，
两端各一处。修完同一处像素从 `#F0F0F0` 变成 `#1A2B2C`，那段说明文字的对比度从
**1.0:1** 变成 **7.42:1**。

教训：**对比度算得对，不等于界面上看得见。** 那 12 条算对比度的单测测的是「色板里
这一对色值」的关系，测不到「文字压在哪个容器上」；容器底色属于布局，不属于色板。

### 深色标题栏：系统画的那条也得跟着变

内容区修好了，窗口顶部还剩一条系统画的标题栏 —— 浅色主题下看不出，深色主题下就是
一块白条压在深潭青上面。Compose Desktop 没有跨平台的「深色标题栏」开关，Windows 上
唯一的入口是 DWM 的 `DwmSetWindowAttribute`（属性号 `DWMWA_USE_IMMERSIVE_DARK_MODE`，
Win11 与 Win10 20H1+ 是 20，更早的是 19）。

做法写在 `app-desktop/.../WindowTheme.kt`，只有 app-desktop 知道这件事（core / ui 不该
知道宿主是什么系统）。三处坑：

1. **拿不到 HWND。** 常规写法是反射 `WComponentPeer.getHWnd()`，但那是 JDK 内部实现类，
   JDK 17 起模块系统默认封着 —— 实测抛 `InaccessibleObjectException`，被 `runCatching`
   吞掉后只剩 `null`，日志里表现为「每次都拿不到 HWND」。改成问系统：`EnumWindows`
   列出所有顶层窗口，挑进程号等于当前 JVM 且可见的那些，再按 AWT 那边的窗口标题认人。
2. **设上了也可能不重画。** 属性返回 0 只代表系统收下了，标题栏不一定立刻重画。补一次
   `SetWindowPos(..., SWP_FRAMECHANGED)` 让系统按新属性重算非客户区；再用
   `DwmGetWindowAttribute` 回读一遍，确认真记住了才算成功。
3. **`PrintWindow` 截图看不出效果。** 它重画标题栏时不走 DWM 合成器，永远画出系统默认
   的浅色那条 —— 哪怕属性明明设上了、回读也是 1。所以这一项只能靠人眼在桌面上看，
   自动化截图会给假阴性。

失败一律静默：非 Windows、换过别的 JVM、窗口 peer 还没建好，结果都只是标题栏保持系统
配色。第一次调用经常赶在 peer 建好之前，所以调用方（`Main.kt`）隔 250ms 再试一次，
两次都不成才安静放弃并打一行日志。

## 四、界面

「设置 → 界面」从「全是只读信息」变成真的能选：三行选项，每行左边一块双色小样
（底色 + 强调色）、中间名字与一句说明、右边选中打勾。第一行「跟随版本」底下会写
「现在用的是「特工蓝橙」」，否则用户看不出自己正看着哪一套。

点一下立刻换皮并落盘，**不跟底部「保存」按钮走**：换配色是即时反馈的事，
点完还要再点一次保存，中间那一眼看到的新颜色就像没生效。这与「设置 → 账号」
里选账号、存 Client ID 的处理一致。

## 五、实测

- `:core:test :ui:jvmTest :ui:compileKotlinJvm :app-desktop:compileKotlin :androidApp:assembleDebug`
  全部 EXIT=0，**54 个测试类 / 635 例全过**（改造前 53 / 623）。
- 新增 `LauncherThemeTest` 12 例，其中四条是**算对比度**的，不是「看着差不多」：
  正文压在自己底色上 ≥ 4.5:1、强调色上的字 ≥ 4.5:1、卡片与底色的层次在 1.05–3 之间、
  所有色值都是不透明的（漏写一位 `0xFF` 会变成半透明，界面上看着像没生效）。
- GUI 实点：孵化版启动后默认是特工蓝橙（浅色）；「设置 → 界面」点「自然原色」，
  界面立刻换成深潭青 + 泥土棕，`settings.json` 的 `theme` 变成 `"natural"`；
  关掉重开仍是自然原色；再点回「跟随版本」，值变回 `"auto"`、界面回到浅色。
- 深色下一路点过设置 / 界面 / 启动 / 实例 / 下载 / 光影包 / 服务端 / 账号 / 关于九页，
  逐张截图并做近白像素扫描：修完根容器底色后，整窗剩下的近白像素只剩标题栏 ——
  于是又在第三节末尾补了一节「深色标题栏」。

## 六、还没做到

- 只有两套，没有自定义色、没有单独的深/浅切换（每套自带一个明暗属性，绑在一起的）。
- 安卓端没有真机跑过；配色选择在安卓设置页第一张卡，逻辑与桌面一致。
- 只逐页截图核对了两套配色下的主要页面（九页），弹窗、输入框获得焦点、
  危险操作的红底提示这些状态没逐一核对。
- 安卓端的系统状态栏 / 导航栏没跟着配色走，同样是平台侧的事。
- 深色标题栏只在 Windows 上做了；macOS / Linux 上标题栏仍是系统配色。
