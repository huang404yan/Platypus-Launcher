# 自己申请一个 Azure 应用 ID：正版登录前的三分钟

2026-11-14。0.8.0-preview.10 起，安装包里**不再内置任何 Client ID**，正版登录要用一个你自己注册的。

这篇是那件事的操作手册，界面里「设置 → 账号 → 第一步」那张卡是它的缩写版。

## 一、为什么不内置

微软不发放通用的客户端 ID。任何一个随安装包发出去的 ID，实际含义都是
**所有下载了这个包的人共用一份别人名下的应用注册**，由此带来三个问题：

1. **配额是共享的**。这个 ID 上所有调用都算在注册者名下，用的人一多就被限流，
   表现是「昨天还能登录，今天一直报错」，而拿到安装包的人无从处理。
2. **随时可能被收紧**。注册者发现名下多了一堆不是自己发起的调用，把公共客户端流一关，
   所有依赖它的包当场全部失效。这不是假设 —— preview.9 之前用的是 Azure CLI 的 ID，
   它之所以能过，纯粹因为那是微软自家应用、没人去关。
3. **仓库是公开的**。内置就等于把别人的应用 ID 写进版本历史，谁都能抄走拿去用，
   责任却还算在人家头上。

所以从 preview.10 起，登录流程第一步是「填一个自己的 ID」，填完存在本机的
`<游戏目录>/platypus/settings.json` 里，**不进安装包、不进仓库、不上传任何地方**。

代价是每个新用户要多花三分钟。这三分钟换来的是：你的账号只经你自己注册的应用，
限流与失效都由你能处理。

## 二、申请步骤（Azure 门户，免费，不需要订阅）

界面上只写了四步，这里补上每一步为什么这么做。

### 1. 打开 portal.azure.com，登录

哪个微软账号都行，**跟要玩的游戏账号可以不同**。这个账号只是「这个应用注册在你名下」，
不参与游戏登录；正版登录时输的是你自己的 Minecraft 账号。

没登录过 Azure 的话会看到一个引导页，选「继续」即可，会免费创建一个默认目录
（Microsoft Entra ID 租户），不需要绑卡、不需要订阅。

### 2. 进「Microsoft Entra ID → 应用注册 → 新注册」

- **名称**：随便填，例如 `platypus-launcher-mine`。它只出现在你自己看的列表里。
- **受支持的账户类型**：选「仅此组织目录中的账户」**以外**的任何一项都可以。
  设备码流程走的是 `consumers` 租户，选到「仅此组织目录」会登录失败。
- **重定向 URI**：**留空**。设备码流程不需要它，填了反而多一个要维护的东西。

点「注册」。

### 3. 在「身份验证」里打开「允许公共客户端流」

进刚建好的应用 → 左侧「身份验证」（Authentication）→ 拉到最下面
「高级设置」里的「允许公共客户端流」（Allow public client flows）→ 选**是** → 保存。

这一步不能省。桌面应用没有后端服务器，令牌是直接向微软要的，属于「公共客户端」；
关掉的话，拿设备码换令牌那一步会被拒，报错是
`unauthorized_client` 或 `invalid_client`。

外观上这个开关在部分界面语言下叫「启用以下移动和桌面应用程序流」，意思一样。

### 4. 回到「概述」，复制「应用程序(客户端) ID」

那串 36 位、带四个横线的十六进制字符串，例如
`00000000-0000-0000-0000-000000000000`。粘进「设置 → 账号 → 第一步」下面的输入框，
点「保存 ID」。

保存后立刻生效，**不用重启启动器**：Client ID 是每次登录与刷新时现读设置的，
不是启动时读一次就不变了。

## 三、范围与限制

- 登录用的是 `XboxLive.signin offline_access` 两个 scope，只要这两项。
  不需要 `User.Read`、不需要目录权限、不需要管理员同意，**不会**请求任何超出登录所需的东西。
- 应用注册在你自己的账下，随时能在门户里删掉；删掉后启动器这边的正版登录就会失效，
  改用离线模式即可，不影响已有实例与存档。
- 同机上多个游戏目录可以共用一个 ID，各存各的 settings.json。

## 四、常见报错对照

| 界面上的话 | 实际原因 | 怎么办 |
|---|---|---|
| 这个 Client ID 不被微软接受… | ID 打错了，或第 3 步的开关没开 | 回门户核对 ID 与「允许公共客户端流」 |
| 还没有填 Client ID，正版登录用不了 | settings.json 里是空的 | 走一遍本页第二节 |
| 这不像一个应用 ID… | 粘进去的是别的字符串（应用名、目录 ID） | 要的是「概述」页最上面那行「应用程序(客户端) ID」 |
| 换过 ID 之后报 invalid_grant | 微软把 refresh_token 绑在应用上，换 ID 等于换应用 | 在账号页把旧账号「移除」再重新登录 |

最后一条是这个设计里唯一会咬人的地方：**登录用哪个 ID，刷新就必须用同一个**。
所以启动器里登录与刷新都从同一份设置现读，改动 ID 之后旧账号必须重登一次。
`AccountAuth.kt` 的 KDoc 里写了这一条。

## 五、这个 ID 会不会泄漏隐私

不会。它只是一个公开标识符（OAuth 的 `client_id` 本来就随每个授权请求出现在表单里），
**不是密钥**：公共客户端没有 client_secret，拿到 ID 的人也没法冒充你的应用去读你的数据。

真正等价于账号密码的是 `<游戏目录>/platypus/accounts.json` 里的 refresh_token，
那个文件不随任何输出物分发，只存在本机。

不过界面上还是默认把它遮起来了（照 PCL 自用版的做法）：输入框里显示的是一串圆点，
要看明文得按住旁边的「按住显示」，松手立刻恢复；这个框**不允许复制**，只保留粘贴 ——
从 Azure 门户抄进来是正常用法，抄出去没必要。

拦的位置是**写剪贴板那一层**（给输入框换了一个只读的剪贴板实现），所以 Ctrl+C、右键菜单、
菜单栏 Copy 三条路一起失效，不是只堵键盘。这一点是实点验证后才改对的：最初只在
`onPreviewKeyEvent` 里拦 Ctrl+C，提示条弹出来了、按键也消费了，但剪贴板里照样被写进了明文 ——
说明 Compose Desktop 的复制不全走键盘分发。框下面会给一句提示说明为什么没复制成。
切走窗口时按住状态也会自动收掉，免得按住后 Alt+Tab 一直露着。

这不是限制功能：ID 存在设置里，随时可改、可重新粘贴、可按住看一眼。遮的只是「共享屏幕
或截图时白送一个能定位到谁的应用注册的指纹」。

## 六、发布时的约定

测试版（`0.8.0-preview.N` 这条孵化线）打包与发布时：

- **不内置任何 Client ID**。`MicrosoftEndpoints.DEFAULT_CLIENT_ID` 保持空串；
- **不带任何含隐私的内容**（账号、令牌、本机路径、诊断页导出的现场）；
- **必须带上本页的指引**：安装包旁边至少要有能指向这份文档的东西 ——
  Release 说明里有一段、界面「设置 → 账号」第一张卡里有一份缩写。

规则本身写在 `releases/README.md` 的「不放什么」一节。
